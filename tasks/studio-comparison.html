What Tirs Could Adopt

High Value — Easy to Add
  • Hooks — Session Start/Stop: Auto-load recent agent-log, check for stale tasks, dump session summary on exit. Currently Tirs relies on CLAUDE.md instructions for this, but a hook would enforce it.
  • Hooks — Pre-Compact: Save working state before context compression. Prevents losing context mid-session.
  • Status Line: Show current phase, active faction, round number, or context usage %. Quick orientation.
  • Settings Permissions: Lock down destructive git commands and sensitive file access in settings.json.
Medium Value — Worth Considering
  • Path-Scoped Rules: E.g., WebApp/game-*.js → "never touch Board rendering", WebApp/abilities.js → "data-driven, no hardcoded targeting". Currently this lives in CLAUDE.md which is always loaded anyway.
  • Agent Tool Restrictions: QA agent shouldn't Write files. Designer shouldn't run Bash. Prevents agents from drifting outside their lane.
  • Commit Validation Hook: Check for console.log debris, hardcoded hex coordinates, missing undo snapshots before commits.
  • Document Templates: Standardize ability spec format, faction design docs, bug report structure.
What Tirs already does better: The self-improvement loop (lessons.md), structured typed memory system, live external data integration (Google Sheets), and the data-driven ability architecture are features that Game Studios doesn't have. Tirs' CLAUDE.md is also significantly more useful — it contains actual architecture knowledge rather than just pointing to docs.

Design Philosophy

Game Studios

"Question → Options → Decision → Draft → Approval"

  • Agents never auto-execute; always present options
  • "May I write this to [filepath]?" before every modification
  • User is the decision-maker at every step
  • Collaborative Design Principle: 22.4KB document codifying this
  • "The file is the memory, not the conversation"
  • Context budgets: light ~3k, medium ~8k, heavy ~15k tokens
Optimized for exploration and safety — you're building something new and don't want surprises.
Tirs of Traea

"Plan → Execute → Verify → Learn"

  • Plan mode for non-trivial tasks, then autonomous execution
  • Subagents for parallel research, keep main context clean
  • Self-improvement: log mistakes in lessons.md, write prevention rules
  • Demand elegance: "is there a more elegant way?" before presenting
  • Autonomous bug fixing: "just fix it, don't ask for hand-holding"
  • Agent routing table: classify task → route to correct agent(s)
Optimized for velocity and domain expertise — the architecture is known, ship features fast.

Bottom Line

Game Studios excels at…
  • Infrastructure: hooks, rules, permissions, status line
  • Process: structured workflows, gate checks, release pipelines
  • Breadth: 48 agents covering every game dev discipline
  • Safety: explicit allow/deny, validation hooks, anti-patterns
  • Onboarding: /start command with 4 branching paths
  • Documentation: 60+ pages of workflow guides and examples
Tirs excels at…
  • Domain depth: agents understand hex grids, LoS, ability systems
  • Real integration: live Google Sheets data, actual game code
  • Learning: self-improvement loop catches and prevents mistakes
  • Velocity: autonomous execution with plan-mode guardrails
  • Architecture docs: CLAUDE.md teaches the actual codebase
  • Structured memory: typed files with frontmatter, indexed
They solve different problems. Game Studios is a process framework — it's brilliant for starting from zero and maintaining discipline across a large, engine-backed project. Tirs is a domain-expert configuration — it's brilliant for moving fast on a specific, well-understood codebase. The best version of Tirs' setup would cherry-pick Studio's hooks, path rules, and permission lockdowns while keeping its own domain-specific agents, memory system, and self-improvement loop.
